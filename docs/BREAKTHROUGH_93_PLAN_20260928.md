# 从 92.48 到 93 分以上：突破路线、具体模型与止损安排

> 编写日期：2026-09-28，Asia/Shanghai。
> 证据版本：`ad050127cfd8e7be271edc83db5021602a62f236`，状态记录截至 2026-09-27 23:30。
> 文档性质：研究建议，尚未实现或验证的新方案。此次只编写报告，没有执行求解、修改算法或提交比赛结果。
> 官方已兑现基线：`cand_merge2`，92.48；对应本地记录 92.4751。后续若已有更好计划，所有预算、边际价格和对照必须改用新基线。

## 1. 需要改变的规划判断

目前已经证明：合法性修复有效、评分器能够预测多份正式回执、重定量和重启能产生真实增益。尚未证明：在现有方案附近继续重启，能够补齐到 93.0 的约 0.525 分差距。[E1][E2]

下一阶段建议保留有限的成熟精修预算，把主要研究投入放在**直接生成符合接续规则、但订单链与轮边界不同的完整方案**。先找到一个可解释的合法改进样例，再把它变成算子。不要先开发一套大框架，再寻找它为什么会有用。

本文给出三条有先后关系的路线，不建议同时开工：

| 顺序 | 路线 | 新增能力 | 预期角色 |
|---|---|---|---|
| A | 完整批次的联合配料与材料—刀数前沿 | 联动全部轮、完整 count 域及五坯型，提供域内最优性信息 | 先诊断固定结构的剩余空间，也作为后续重建内核 |
| B | 合法订单链重排与轮边界重建 | 更换谁与谁相邻、谁跨接缝、在哪里分轮；构造阶段就满足接续 | 最值得验证的结构突破路线 |
| C | 完整合法方案池的组合选择 | 将不同批次划分的候选组合成每订单恰好出现一次的计划 | 只有 B 能有效生成候选后才启用 |

这三条均无已测增分承诺。“有希望”的依据是它们明确扩大了已测试的表示或优化范围，同时保留严格可行性；不是因为算法名称更复杂。没有第一梯队方案源码和分项指标，不能声称这些就是对手的方法。

## 2. 把 93 分写成数值目标

基线记录为：`K=184494` 刀，成材率显示为 `94.47%`，覆盖 `9998/9999`，本地分 `92.4751`。[E1]

令需求总质量 `D=506157994 kg`、申报材料总质量为 `M`、共享订单数为 `H`。在当前适用的非封顶刀数区间：

```text
S(K,M,H) = 6400000 / K + 40 D / M + 20 H / 9999
```

由四位小数本地总分反推，成材率约为 94.4691%，M 约为 535.792 百万 kg。这里是规划近似，不是对 `plan_merge2.json` 的独立重算；正式实验须读取真实计划和精确账单。

| 情景总分 | 基线尚差 | 固定当前刀数与覆盖时需要的成材率 | 对应约需减少的账单 |
|---|---:|---:|---:|
| 93.00 | 0.5249 | 95.7813% | 7.34 百万 kg |
| 93.20 | 0.7249 | 96.2813% | 10.08 百万 kg |
| 93.50 | 1.0249 | 97.0313% | 14.15 百万 kg |

另一条联合坐标是 **183500 刀、95.32% 成材率、当前覆盖率，约得 93.0034**。它要求约少 994 刀，并把材料效率提高约 0.851 个百分点；并不意味着这几个指标能同时达到。

此前从数据得到的乐观刀数下界仍有用：片段至少 173769，按钢种规格分组的轮数至少 8571，总刀数至少 182340。轮数界来自每轮最多交付 `60000×148/150=59200 kg` 净物料。保持最新材料效率，即使达到该刀数下界且覆盖满分，总分也至多约 **92.8869**。该界忽略许多约束，两个下界也未必同时可达；它足以说明材料改善仍是必需的。[E3]

**93.0 是研究情景线，93.2 是可考虑的内部缓冲目标，都不是前十排名保证。**榜单会变化，不能把一个旧的分数区间当最终门槛。

## 3. 已有负结果如何使用

以下工作不应以原样重新列入待办：

- `allow_illegal`、筛选符号、整轮腾空计刀等修复：已完成，作为固定基线。
- 两轮“少一根坯”探针：全批扫描收益小，而且已被生产版 kicks 复现或超过；不再独立扩量。
- 分子口径对照：已做小样，未发现值得扩大的收益；正确口径用于最终评价，但不全卷重跑旧谱系。
- 旧 from-scratch 联合重建：已有接续违规；不重复使用同一生成器尝试冲榜。
- 文档和注释卫生项：不作为增分路线。

关闭实验不等于证明整类问题最优。下一步能否重开，取决于有没有**具体改变失败机制**：

| 已测证据 | 能说明什么 | 不能外推成什么 |
|---|---|---|
| 两轮普查没有超时 | 已枚举域完成 | 所有 count、坯型、轮数、订单归属均已穷尽 |
| 最小组跨批重建更差或非法 | 那套构造不值得扩量 | 所有合法跨批组合都没有收益 |
| 新旧分子口径对照不赢 | 小幅价格修正不值得继续铺开 | 所有新订单链都会回到同一最优值 |
| Wave I 比 H 再涨 0.0069 | 成熟路线还有尾部收益 | 再加预算足以到 93 |

具体地，`blank_step.py` 固定当前坯型与订单支持集，count 网格为 `max(1,c-spread)..min(cap_c,c+2)`，件数还受到 `slack` 域限制。`complete=True` 的严格含义应当是这个枚举域完成。本文不建议简单放大该探针；这些范围说明为什么完整批次诊断仍然是不同的问题。[E4]

## 4. 路线 A：完整批次的联合配料，先量出“当前形状还差多少”

### 4.1 第一版只固定现有订单支持集

选一个完整合法批次，固定轮数 R、轮序，以及每轮出现的订单集合。最多六轮。不改变批次成员，不进行跨批重建。这样接缝结构和覆盖关系保持不变。

对该批枚举五种坯型，每种坯型内联合决定：

- `c_r`：第 r 轮并排根数，整数；
- `k_ir`：订单 i 在第 r 轮的每根片段数，整数；
- `n_r`：第 r 轮申报坯数，整数。

设订单定尺为 `s_i`，同规格线密度为 `ell`，坯型重量为 `w`，订单最少交付件数为 `P_i`：

```text
L_r = sum_i s_i k_ir
48 <= L_r <= 148
1 <= c_r <= floor(2000 / diameter)
(L_r + 2) c_r ell <= 60000
(L_r + 2) c_r ell <= n_r w
sum_r k_ir c_r >= P_i
k_ir >= 1  在原正支持集上；其余 k_ir = 0
K_batch = sum_ir k_ir + R
M_batch = w sum_r n_r
```

`P_i` 必须由当前物理交付口径导出，最终还要按真实质量校验。模型中的 epsilon、整数倍边界应与生产计量一致，不能以放宽欠交或少报材料得到优势。

### 4.2 具体求解方式

小批次优先采用完整有限 count 域的整数模型。可为每轮每个合法 count 设置选择变量 `z_rt`，并为每个订单设置 `q_irt`，表示选 count=t 时的片段数：

```text
sum_t z_rt = 1
0 <= q_irt <= U_ir z_rt
在正支持上 q_irt >= z_rt
交付 = sum_rt t q_irt
刀数片段 = sum_irt q_irt
用料_r = ell * (sum_it s_i t q_irt + 2 sum_t t z_rt)
```

长度、用料、交付、坯数和刀数约束由此均可写成线性形式；`U_ir` 必须是由定尺与床长推得的有效上界。该展开可能较大，所以先从少订单批次开始，不把它直接套到一万单。使用已有且符合比赛规则的求解环境；仓库规则称商业求解器仅限 COPT，不为此另引入未经确认的商业依赖。[E6]

第一版诊断也可枚举完整 count 元组后求整数配料，但六轮乘积可能爆炸。**若只保留 count 短名单或设置 beam，就改称启发式，不能再声称证明域内最优。**

### 4.3 不只求一个固定价格下的最优解

对不同刀数预算 `K_batch <= kappa` 分别最小化材料，保留不被支配的 `(K_batch,M_batch,H_batch)`。固定支持时 H 不变。某个配置在当前价格下略差，可能帮助识别应当寻找的材料—刀数交换；但只有精确全局分数提高才进入可提交候选。

初始刀预算至少包含当前刀数及其邻近档位。允许增加刀数的范围由对应材料目标能否补偿来决定，不能只搜索“不加刀”。五种坯型的最优值一起比较；旧轮型上排名第三的坯型，可能在新配置下胜出。

### 4.4 本路线的判断价值

- 如果 A 能构造明显更好的合法配置，说明当前数值搜索遗漏了组合；研究更快的联合配料或 warm start。
- 如果 A 获得接近当前解的有效最优性界，说明继续在这批的固定支持内重启价值小，应转向 B。
- 如果超时且上下界很宽，只能说这个求解方法暂时不合算。

即使 A 完成，也只认证该批、该支持集和模型域；不能认证其他轮结构。若分开求材料下界与刀数下界，将二者用于乐观分数上界是安全的松弛，但不能把二者拼成一份可行计划。

## 5. 路线 B：直接生成合法订单链，再联合选择轮边界

### 5.1 这是最值得押注的结构变化

报告显示全卷大量接缝是单订单交班。它限制了一个接缝同时跨越的订单数，却没有规定**必须由当前这个订单交班，也没有规定其他订单的排列必须不变**。

已有两轮探针固定了每轮订单集合。B 明确放开这些变量：订单排列、每轮包含的订单、跨轮订单身份、分轮位置、轮数及每轮 count。第一阶段仍固定完整批次成员，避免重开大范围组批搜索。

### 5.2 一种可实现的合法表示

把本批订单排列成一个序列，每个订单的交付构成一个连续块；将该序列切成至多六轮。轮边界最多切开一个订单。若同一订单连续经过多轮，则中间轮只能承载该订单，直到该订单结束后才进入下一个订单。

这是一种满足当前接续判据的**充分构造**，不声称已经证明覆盖所有平台合法形状。轮内键顺序由此生成，不能事后任意排序。

对一个固定订单序列，用“完成前缀 + 当前订单未交付件数 + 已用轮数”为核心状态。还需记录当前订单是否已获得共享覆盖；已完成订单的覆盖计入标签。一次转移生成一整轮：

1. 选择合法 count 和该轮片段分配；
2. 检查 48–148 m、60 t、床宽与整数定尺；
3. 更新订单剩余交付，结束的订单永不重新出现；
4. 累计精确整数账单、片段数、轮数及覆盖；
5. 只在相同未来状态下做合法的标签支配删除。

标签保留材料、刀数和覆盖的非支配组合，不能只保留最低材料路径。对每种固定坯型完成一遍，比较五种结果；同一方案内不得擅自给不同轮选择不同坯型。

工程上允许先做 beam 版本找可行改进，但它不提供最优性证明。小实例用完整枚举或路线 A 的扩展模型校验，防止把启发式截断误说成没有空间。

### 5.3 第一版只做三种订单序列变化

不要一开始枚举全排列。以当前合法顺序为起点，每个变体都重新求整批轮边界与 count：

- **相邻交换**：交换两个完整订单块，改变与接缝相邻的定尺组合；
- **短块插入**：把一个或两个完整订单移到本批另一个位置，让原先独占一轮的短订单与不同邻居共享；
- **三订单重排**：选一个跨两个接缝的局部区域，枚举其中三个完整订单的六种排列，检验需要多个接缝共同变化的改进。

关键是“交换后从合法表示重新求轮”，不是把旧轮里的订单直接挪过去并容忍接续违规。只调换 JSON 键序也不是这个动作。

### 5.4 为什么它可能越过目前的平台

示意上，当前相邻轮可为 `[A,B] | [B,C] | [C,D]`。若改变完整订单顺序，新的合法链可能让另外的订单承担接缝，并改变各轮允许的交付组合与 count。当前对固定支持集的两轮搜索无法评价这类整体变化。

这个示意没有具体订单重量，不是一个已验证的改进例。真正启动扩量的条件，是在真实小批次里产出至少一个严格校验通过、优于生产精修等预算结果的例子，并解释它改变了哪些接缝、轮边界及账单整数档。

对少数固定支持已经很紧、但材料损耗较大的批次优先诊断。损耗大不是必然可省，仍要结合 A 的界限与实测。

### 5.5 本路线的首个交付物

不是一张全卷预测分表，而是一个可核对的前后对照：

```text
同一批订单；旧/新订单链；旧/新每轮 count；旧/新交付；
旧/新整数坯数；旧/新 K/M/H；严格校验结果；精确全局 delta_score；
相同时间预算下生产精修的最好结果；种子与候选版本。
```

如果所有改善都能被生产版 kicks 在更低成本下复现，B 不升级成主线；若 B 只改变了数值，没有改变订单支持或轮边界，应归入 A 的改进，不冒充结构突破。

## 6. 路线 C：完整合法方案池，解决“各自不错但拼不起来”

**启用条件：B 已经能稳定生成不同合法形状，而且已有少量同组批次成员变化的合法候选。**否则 C 没有可组合的材料，不开发主问题。

从同钢种、同规格的 2–4 个现有批次出发。保留全部原方案，再少量生成“完整订单迁移/交换后的合法方案”。生成必须使用 B 的接续构造；原先不建模接续的 from-scratch 不能作为候选来源。

每一列 p 是一个完整合法方案，含订单集合 `O_p` 及 `(K_p,M_p,H_p)`，轮数不超过六。主问题选择列：

```text
x_p in {0,1}
对每个订单 i：sum_{p: i in O_p} x_p = 1
K = sum_p K_p x_p
M = sum_p M_p x_p
H = sum_p H_p x_p
```

因为订单恰好归属一列，覆盖数可以按列相加；不允许用跨方案拆同一订单的方式填满冷床。原方案全部留在池里，因此组合问题始终有原计划作为可行回退。

第一版在几个 K/H 预算下最小化 M，得到候选，再按完整计划精确评分；不需要一开始实现全量列生成。每个局部窗口只生成有上限数量的列，避免候选池指数增长。

它与此前“整个组贪心重排，然后整组接受或回退”的差别是：可以组合局部有效的完整方案，不必吞下同组其他位置的退化。**但主问题只对已生成列负责；池内最优绝不等于原问题全局最优。**

若 B 已饱和而候选池成员集合又完全相同，C 只是每批挑选版本，价值有限；不得因此继续建设复杂主问题。只有出现实测有希望的合法成员变化，才满足重开跨批方向的条件。

## 7. 不做第四条大路线：辅助措施附着在 A/B/C 上

### 7.1 建立材料—刀数—覆盖候选档案

当前总分略低的候选不必立即删除，但只保留非支配方案，并记录适用订单集合。同一集合中，如果方案在 K、M 都不更好且 H 不更高，则通常可直接淘汰；只在结构多样性有明确后续用途时限额保留。

可以让同一个生成器以少量不同的材料/刀数价格生成候选，例如当前边际价格的 0.5、1、2 倍。它只是扩大候选前沿，最终仍用原评分；与已经关闭的约 1% 分子修正实验不是同一个问题。若三档生成相同结构或没有可用前沿，不继续扫参数。

### 7.2 分配重启预算，而非所有批次等额加码

成熟精修保留约 20% 预算。按近期单位计算时间的实际增益排序，给未试批次保留少量探索预算；对连续两档追加预算都无新增收益的批次暂停。不同批次并行可以保留，不用重新搭建任务调度系统。

长任务继续使用现有 `task_watcher`。需要 heartbeat 且用户未指定间隔时按 30 分钟；只在完成、失败或需要决策时通知，不密集轮询。

## 8. 如何验证“有希望到 93”，而不是再得到几笔零碎收益

### 8.1 三类样本承担不同任务

- **小模型校验样本**：选易于完整求解的批次，确认模型与校验器一致；不用来估计全卷收益。
- **高潜力样本**：按材料损耗、约束松弛界和结构特点排序，尽快寻找合法改进；成功率不能直接外推全卷。
- **保留样本**：从主要规格、不同规模和轮数层中抽取未用于调参的批次，评估可迁移性。记录抽样方式。

此前最大的两个钢种规格组 NP01/43 与 C60/26.5 合计约占需求质量 58.2%，应纳入代表性评估，但不能按质量占比直接分配全部预算。最小组上的失败也不能代替它们的评估。[E3]

### 8.2 对照必须包含生产移动集

报告已经记录过“不带 kicks 的退火”与“生产 kicks”能力差异。新方法必须对比当前生产配置，限制相同 CPU 总量或清楚标注的墙钟/核心数；构造、修复、精修时间均计入预算。若算法成本差异大，相同重启次数不构成公平对照。

结果表至少包含：基线哈希、模型域、配置、种子、CPU 时间、合法率、K/M/H 变化、全局精确增分、求解界限与状态。随机方法先看少量配对种子；最高分比赛允许尾部收益有价值，但单个幸运样本只触发一次有限复核。

### 8.3 三本账，不能混为一个承诺

1. **已兑现账**：将无冲突补丁实际合并，完整校验并重算得到的总分。
2. **经验机会账**：代表性样本揭示的潜力，明确抽样偏差和不确定性。
3. **乐观界限账**：模型松弛给出的上界，只用于排序和排除。

同一批次的多个改善不能相加；不同实验对同一材料损耗的改善也不能相加。即使批次互不冲突，各批相对同一基线计算的 delta_score 也不能直接当精确总增分：先累加真实 delta_K、delta_M、delta_H，再评价一次完整计划。

建议将实际全卷 **+0.05** 作为继续扩量的一道管理门槛，而非理论阈值；廉价的 +0.01 可以保留，但不能凭此支撑多天研发。要成为冲击主线，还应有明确证据说明剩余范围如何继续贡献到约 +0.525，而不是把最好样本乘以批次数。

例如，在规模约 535.8 百万 kg 的账单下，不增加刀数时，省 1 百万 kg 约值 0.071 分。这说明突破需要百万 kg 级别的累计有效改善。新增刀数会抵消收益；减少刀数可降低材料要求。

## 9. 分阶段安排及停止条件

以下是建议预算，不是已创建的任务，也不是算力收益保证。当天先查当前任务占用，不打断已有搜索。

| 阶段 | 预算建议 | 必须交付 | 不满足时如何停止 |
|---|---|---|---|
| 0：冻结基线 | 30 分钟内 | 当前最好合法计划的精确 K/M/H、版本和哈希 | 缺失就补现有记录，不重新审计整个项目 |
| A：小批联合模型 | 原型最多半天；诊断总计不超过一天 | 模型一致性、可行改进或有效界限 | 模型失配或多数样本只超时，不扩到全卷 |
| B：合法链动作 | A 明确显示结构受限后启动；先半天小样 | 至少一个解释清楚且优于等预算生产精修的合法例子 | 无新结构、收益被原算子更便宜复现，则关闭 |
| B 扩量 | 先独立保留样本，再选定范围 | 合并后的真实收益与单位成本 | 增益不能迁移、成本失控，则保留结果并停止扩量 |
| C：局部列选择 | 仅在候选生成门槛满足后，半天验证 | 小窗口候选池及组合改善 | 列不多样或池内选择不改善，不做全量列生成 |
| 最后交付阶段 | 建议结果截止前至少留 24 小时缓冲 | 最好包、回退包、Linux 复现与提交证据 | 不再引入缺少收益证据的新架构 |

默认预算比例可取：成熟精修 20%，一条突破实验 60%，验证/交付/机动 20%。阶段不通过时释放预算，不自动转成更多同类重启。

如果 A 证明固定形状很紧，B 又不能产生更好合法形状，而 C 未满足启动条件，应明确记录“当前尚无支持冲过 93 的新路线”。保住最佳成绩，继续低成本收益，不用更多实验名称掩盖这个事实。

## 10. 实现交接清单

以下文件名只作未来实现建议，本报告没有创建这些程序：

| 建议组件 | 输入/输出 | 核心要求 |
|---|---|---|
| `tools/analysis/batch_frontier.py` | 当前完整批次 → 非支配配置、模型域、界限 | 五坯型、完整声明 count 域、固定支持、整数配料 |
| `tools/analysis/chain_rebuild.py` | 批次订单序列 → 合法轮序和配置 | 订单连续、单订单交班、至多六轮、精确账单 |
| `tools/analysis/scheme_pool.py` | 合法完整方案池 → 恰好覆盖订单的组合 | 原计划可回退、禁止跨方案拆单、池内最优范围明确 |

统一数据契约应包含：`base_plan_sha256`、`data_version`、`score_version`、`domain`、`seed`、`cpu_seconds`、`status`、`K/M/H_before_after`、`delta_score_exact`、`bound_scope`。状态至少区分可行改善、限定模型内已证明最优/无解、时间或状态预算耗尽。

有代表性的必要校验包括：

- 不优化、原样输入时重建后保持交付与 K/M/H；
- 同订单跨多轮时没有跳轮和非法插入；同一中间轮两端共享同一订单时，只承载该订单；
- 确保取整边界、50/150m、60t、六轮、整数定尺和真实质量足额；
- 小实例用独立枚举核对模型最优值；启发式算法不冒充精确结果；
- 每个导出候选同时通过现有严格校验、当前评分器和独立的物料/订单计数检查；
- 合并候选后再对完整计划校验、计分和记录哈希；本地通过仍不称平台认证。

源码按现有目录规则管理，生成物放 `artifacts/runs/`，原始回执和已提交包不改写。实际比赛提交遵守已有用户授权与配额，报告上传不等于授权启动上述实验。

## 11. 建议优先批准哪一步

最小有价值的下一步是：**用小批次的联合整数模型，取得一个当前生产搜索尚未找到的合法配置，或证明几个代表性固定形状确实已很紧。**

A 的价值是避免盲目选算子；B 的价值是改变合法形状；C 的价值是把局部合法候选组合起来。三者依次提供证据，而不是同时建设三套系统。93 分能否达到，最终由真实完整计划回答。
