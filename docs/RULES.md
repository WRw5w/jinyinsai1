## 约束与交付

| 项目 | 复赛口径 |
|---|---|
| 辊道 | 50–150 m，宽 2 m，承重 60 t |
| 冷床轮数 | 每个组合方案最多 6 轮 |
| 组合 | 同钢种、同规格；同一订单不可跨方案，orders 列表不得重复 |
| 连续性 | 同一订单跨轮时相邻连续，不能插入其他订单、不能跳轮；**相邻两轮共同出现的订单最多一个**（09-28 答疑"要求"，实现语义见 [证据](EVIDENCE.md)） |
| 物料 | 每轮钢坯重不低于棒材重；每订单分配重量不低于需求；定尺整数倍 |
| 覆盖 | 除异常订单外，所有订单参与计算 |
| 切损 | 每端 1 m、每轮共 2 m；length_scheme 写净长度。**09-28 确认：钢坯重量下限含切损**（按 `(Σ分配长度+2)×并列支数×单位长度重量`），**内部锯缝不计入**（物理长度取 `L+2`，无 `(K−1)·delta` 项） |
| 并排长度 | 每根棒材上的分配长度；质量乘并排根数，刀数不乘根数 |
| 并排根数 | **counts 可逐轮不同**（09-28 答疑："不要求全程相同"），每轮各写各的 |
| 计刀结构 | 每轮总段数 +1；浮点取整的实际平台口径仍待复赛小分校准 |
| 超产 | 无已声明的超产上限；按复赛答疑，超产不增加成材率分子 |
| 有效组合 | 采用后续答疑的“同轮至少两个订单”口径；不能仅凭在同一方案内就计入（09-28 答疑“不计入”予以确认） |
| 异常输入 | B20270281 原始重量 -25.418 t，现行预处理隔离，不能虚构补值；保留审计 |

条款 6 原文：“同一订单若分在多轮冷床上锯切，其必须在相邻轮次中连续锯切，中间不得插入其他订单，也不得跳轮次锯切”。

## 提交要求

每天最多 5 次，取复赛最高分；结果截止 2026-10-05 20:00，代码截止 2026-10-07 23:59（Asia/Shanghai）。
结果 ZIP 根目录仅放 `复赛结果_团队名.json`；作品另交完整代码、README、至少 3000 字 PDF 技术报告和可复现实现。
最终代码须在 Linux 测试通过，Python 为主或胶水语言；商业求解器仅限 COPT。
当前模型无法保证获得 60 分授奖基线，现有 90+ 预测不可用于作此保证。

**逐条落实**

- **① 内部锯缝不计入。** 问题原话是"校验辊道长度、承重及钢坯足量时，棒材物理长度应取
  `L+2` 还是 `L+2+(K−1)*delta`"，答复"无须考虑" ⇒ **取 `L+2`**，不存在内部锯缝项，
  `delta` 也无规定值。与现行 `chain_layout.length_ceiling(count, linear)` 的
  `(net + 2) × count × linear` 一致。
- **② "任意相邻两轮，共同出现的订单最多一个"是硬要求**（答复"要求"）。
  这正是 `chain_layout` 的接缝结构：每条轮边界上**至多一个订单**两侧都出现；
  推论"A、B 都在连续两轮中加工 ⇒ 违规（共同订单数 2 > 1）"**属于按条款 6 的推理，不是官方明示**
  （09-28 10:15 官方已拒绝再就子问题逐条作答）。同一轮组三个及以上同钢种同规格订单**未被禁止**，
  同样属推理。现行实现（`seam_keys` 只允许单订单跨接缝）与该推理一致。
- **③ 组合覆盖率按同轮计。** 同一组合方案内但**从未同轮锯切**的两个订单**不计入**覆盖率。
  确认现行"同轮至少两个订单"口径；**不能仅凭"在同一方案内"计入**。
