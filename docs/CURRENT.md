`tools/analysis/chain_layout.py` 把方案重新排成"一个交界最多一个跨轮订单"的形状，那是候选判据唯一允许的结构，键旋转做不到。

在 `runs/semi_merged_v4/result.json` 上：布局成功 **2,024 / 3,200**，接缝 7,344 → 3,464（余下全在被放弃的方案里），跳轮 0，质量类错误（`short_delivery` / `order_mass_floor` / `bed_width`）全部为 0。

**还差什么，以及一个必须先定的问题**，见该文件的模块文档。要点：

- 长度上限是**质量决定的**，不是 148 m：46 根并列、43 mm 断面时 60 t 把每轮压到约 89 m。
- 1,173 个方案被放弃，其中 572 个需要的 count 超过床宽上限。原包的 counts 已经顶在上限，且**原包自己就比质量下限少约 3%**——它能过关只是因为 `platform_check` 的质量下限有 `used[oid] == 1` 这个门。
- **实测**：原包按总量口径有 2,050 个订单分配质量不足，其中 2,036 个 `used > 1`（不查），只有 14 个会被查。而平台两次回执**只报跨轮接续，一条质量违规都没有**。所以多轮订单的质量缺口不是平台在管的事。
- 这决定了形状：让订单**跨两轮**（与 `used > 1` 一致）就不会进入那个检查。已有三种构造尝试，**全部输给现在的链条**（1,657 / 660 / 512 vs 2,024），都记在文档里。下次先量过 2,024 再动手。
