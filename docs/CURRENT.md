## 优化（90.59 → 本地 92.1572）

`coarsen → coarsen_mixed → reshape → drop_pieces → reshape2 → repack_counts → reshape3 → retype_and_requant`
（`tools/analysis/shift_cuts.py`），把 220,141 片交付超产花掉 125,057 片、申报质量 −6.25M kg，
覆盖率 +2.27 个点。91.80 之后加的三个遍历（每一个都跑到不动点）：

| 遍历 | 动作 | 未动的东西 | 实测 |
|---|---|---|---:|
| `requantize_cuts`（`--requant-cuts`） | 每批按**统一 count** 重扫（±3），片段由交付下限导出 | 订单集、轮数上界 | 91.80 → 91.99（刀 −242） |
| `recount_rounds`（`--recount-rounds`） | 每轮 count 降到**该轮下限**（RMQ 区间最大值），用刀数换材料 | 片段、切分点 | 91.99 → 92.08（轮 +35、申报 −943k kg） |
| `split_schemes`（`--split-schemes`） | 在**无订单横跨处**把方案切成续段，每段自选坯料重量 | 轮数、count、刀数 | 92.08 → 92.11（申报 −441k kg） |

三者的接受判据都是**同一个汇率**：`2,830 kg × 省刀数 + 申报增量 > 0`（`main()` 的总门控现在也改成这个，
不再只比刀数）。零增量抖动因此消失（每轮净变化 ≈ 0 后停止）。

**跨批重打包**（`tools/analysis/repack_batches.py`，第 92.11 之后的第 4 条遍历）重选**批次组成**
（规则 10 只禁止订单出现在两个方案里，不规定谁和谁同批）：按链长降序首次适应装箱，每批重扫 count 用
`lay_pieces` 从零切，组级门控按同一汇率保留更便宜的方案。**92.1087 → 92.1147**，再级联到不动点
**→ 92.1155**（轮 10,218→10,210，刀 184,521→184,510）。收益只有 +0.0068：同轮"重排批次能省 1,178 轮"

[OVERPRODUCTION_TRIM](OVERPRODUCTION_TRIM.md#跨批重打包重排组成只买到-8-轮)。
详细机制与踩过的坑见 [OVERPRODUCTION_TRIM](OVERPRODUCTION_TRIM.md)。
