（`platform_score.row_metrics` 正是这么算的）；半决赛平台算的是
`min(物理交付质量, 订单登记 weight)`（`platform_score.evaluate`，真径），本卷合计
**506,157,994** kg，比旧式子给的 500,935,599 kg **高 1.03%**。原注释引用了一个
**不存在的函数** `_demand_numerator_mass` 和**初赛**的 96.29%/96.42% 反馈，据此断言这就是半决赛口径——
已改。

**它是常数缩放，不是目标函数差异（09-27 夜定案 —— 含一次自我更正）**。先前看到组间换算因子从
**1.0265（UE505 d=37.5）/ 1.0266（AB-2 d=37.5）/ 1.0386（C60 d=26.5）/ 1.0434（AB-2 d=38.83）
到 1.0598（SALE04 d=27.8）** 不等、组内逐单的登记 weight 与几何质量（`件数 × size × 真径线密度`）
最大差 ±3.14%，据此写过"这是目标函数差异、不是缩放"——**那个推断错了**。理由是：合法的计划必须
**足额交付**（`validate_plan` 拒收欠交），此时 `min(n, 件数) = 件数`、`min(n·size·真径线密度, weight)
= weight` **逐单恒等**，于是两种口径对**任一份合法计划**都各自塌成**常数**：
`finished_old ≡ 500,935,599`、`finished_new ≡ 506,157,994`（实测 `plan_merge2` / `plan_merge1` /
`plan_deep1` 三份足额计划，new−old **都是 5,222,395.4，逐位相同**）。组间因子与逐单偏差只在
**欠交**的计划上才有区别，而欠交非法。**所以旧文那句的前半句是对的，错的只是后半句"不动排序"**：
分子是常数，但 `yield = finished/raw` 的分母 `raw` 会变，缩放**确实**移动"刀 ↔ 材料"的兑换率
（材料被压低 1.03%）。**这才是这条口径的全部影响**——一个约 1% 的边际价格偏差；而且当每个 chunk
都用同一口径的 anchor offsets 时，背景项压过本 chunk 自身的材料，组间因子基本互相抵消。

**改动面比文档原先估的小得多**。物理校验（`make_round` / `validate_plan`）本来就全用真径 kg，
从未漂移；真正需要改的只有 5 处——`Config.numerator_convention`（新字段）、`_capped_finished`、
`order_info`、`plan_capped_numerator` 与 `score_fingerprint`（**缓存键必须带上口径**，否则一个
chunk 会在两种口径之间被重放，正是该字段要防的那类混用）。默认值 `pieces_int` 让**所有现有调用方
和所有已缓存 chunk 逐位不变**。

**开关已落地并验证**：`data/semi/competition.mass.config.json` = 现配置 +
`"numerator_convention": "mass_registered"`；新口径下 solver 的分子与 `platform_score.evaluate`
的分子**逐位一致**（两边都是 506,157,994.0000，`tmp/_numconv_verify.py`；旧口径低 5,222,395 kg）。
`aic.py test` 195 项通过（新增 `tests/test_semi_solver.py::NumeratorConventionTests` 8 项，
含缓存键必须随口径移动的断言）。
