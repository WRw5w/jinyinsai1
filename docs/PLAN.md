# 复赛下一步：先可行，再优化

这是待实施方案，不是完成记录。更新 2026-09-26。

1. **修复放行依据**：补 v4 原始评分回执、阶段和 ZIP 哈希；七个旧候选仅作回归样本。区分格式通过、本地模型通过、官方实测通过。报告绑定实际 ZIP 及内层 JSON；完整比较副本而非比较违规总数。
2. **独立验证条款 6**：使用 [EVIDENCE](EVIDENCE.md) 的候选式，保留未定案标记。回归包括原 v2=7030、v4=7342、官方示例=0、双订单交错、单共享订单正确/错误接续、无交集和跳轮。失败时禁止升级为通过。
3. **改变生成结构**：同钢种同规格内确定订单次序，沿次序依次完成订单；每订单在展开生产序列中只有一个连续区段，相邻轮最多共享一单，跨多轮订单的内部轮次为单订单。不能只保证“订单的轮号相邻”。
4. **生成全量可行基线**：联合搜索并排根数、整数段数、坯型和坯数，重新检查所有 12 条约束；不允许通过欠产、删除订单或跨方案拆单换取连续性。不得把机械拆轮当完整修复，尤其要检查 50m 下限与最多 6 轮。
5. **验证提交**：明确授权后只提交可追溯 ZIP；从该次结果查询记录下载附件核对 SHA，再比较约束数与小分。回读失败标记未知，不能自动反复重交。
6. **再优化与计分校准**：获得有效分后区分浮点取整、权重和子分舍入；用已验证结构做局部搜索/多种子。旧岛只作素材，重新通过约束后才复用。
7. **交付复现**：在 Linux 干净环境复现最终结果，形成真实的代码、数据审计和 ≥3000 字技术报告；按 [RULES](../RULES.md) 的两个截止时间交付。
