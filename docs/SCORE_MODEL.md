# 复赛评分公式（2026-09-26 夜解出；2026-09-27 中午五包逐位对账确认）

**总分 = 0.4×刀子分 + 0.4×成材率 + 0.2×覆盖率**，其中

- 刀子分 = 100 × 160000 / 刀数（基准 160,000 刀；**刀数按四舍五入口径统计**）；
- 成材率、覆盖率就是平台回执报出的百分数本身（91.39 → 91.39 分）；
- **没有时间项**：若存在，其权重 < 0.005（五次回分都在两位小数显示精度内被上式复现）。

**官方分 = 本地分四舍五入到两位小数**——不是"本地 + 某个常数"。下节是五个包的逐位对账。

## "官方 = 本地 × 1.0104" 已作废（那是旧本地代码的口径偏差）

09-26 文档记过"官方成材率 = 本地 × 1.0104"，四发比值一致（1.01038–1.01047）。
**那是本地代码的问题，不是平台的规则**：旧代码把成材率分子算成"直径截断到整毫米"的质量
（初赛口径，偏小 ~1%），复赛平台读的是 `Σ min(实际交付, 需求)`（对本队的盘面数值上
就等于 Σ订单重量）。同一份 `cand_rounded`，旧代码给 90.4428（×1.0104 = 91.383 ≈ 官方
91.39），当前代码直接给 **91.39**。修正落在提交 `69ce957`（09-26 21:33），**早于**
`cand_rp4` 的构造与提交。

**所以这不是把模型拟合到答案上**：公式在 09-26 20:22–20:37 的四张回执上标定，
而 `cand_rp4` 是此后才生成、才提交的包——它的 184,510 / 93.65 / 99.85 三项在**提交前**
就由本地投影写下、**提交后**与平台读数逐位相同，是一次真正的事前预测。
四张回执用于识别模型，第五张（以及 09-27 之后每一发）用于检验它。

## 权重是怎么钉死的

- **成材率 0.4**：#1 与 #5 只差成材率（−4.18 个点；刀数与覆盖率逐位相同）→ 分差 1.672 = 0.4×4.18。
  若权重是 0.30，分差只会是 1.254。官方 PDF 页内的矛盾（权重表 30% vs 公式行 40%）由此定案：**40%**。
- **覆盖率 0.2**：#4 相对 #1：覆盖率 −3.62、成材率 +0.02、刀数 +23。
  −0.724 ≈ 0.2×(−3.62) + 0.4×(+0.02) − 0.4×0.0107，解得 w_覆 = 0.200；#3 独立复算 0.199。
- **刀数 0.4**：由权重闭合（1 − 0.4 − 0.2）与群答疑锚点；未单独做只动刀数的探针（刀数难以独立变动）。

## 三个统计口径

- **刀数——四舍五入（snap）口径**：五个包实报 185,229 / 185,229 / 185,252 / 185,233 / 184,510，
  与本地 snap 值逐位一致；`cand_rounded` 的 floor 值 177,226 被排除。`int(L // size)` 对
  17,029 个书写条目里的 8,003 条差一把（那些小数是二进制双精度下的整倍数少一个 ulp），
  平台读的是**最近的整数**件数。
- **成材率——与本地一致**（五包逐位相同，见上表）；旧 ×1.0104 折算已作废。
  分层要分清：`69ce957` 修的是 **`platform_score`（评分器）**，它此后按真径算。**求解器**
  内部的成材率分子另有一条口径开关（`Config.numerator_convention`，09-27 落地，默认仍是
  初赛的件数口径，与评分器**不一致**），两者何时统一、统一后分数怎么动，见
  [CURRENT](CURRENT.md) 的"已知口径漂移"一节与 `runs/_numconv_ab.sh` 的对照。
- **覆盖率——与本地一致**（97.43 / 97.43 / 93.81 / 96.46 / 99.85 逐位命中，无偏移）。
  分子只数"与别人同处一轮"的订单（`src/platform_score.py` 的 `if len(set(scheme)) > 1`），
  分母 9,999。

## 灵敏度（做优化方向时用）

- 每 +1,000 刀 ≈ −0.187 分（在 185k 刀处）；成材率每 1% = 0.40 分；覆盖率每 1% = 0.20 分。
- cand_rounded 分项离满分：刀 86.38（−5.45）、材 91.39（−3.44）、覆 97.43（−0.51）。

## 用本地数预测官方分

`官方分 = round(0.4×(100×160000/刀数_snap) + 0.4×成材率_local + 0.2×覆盖率_local, 2)`

**残留不确定性（审核时请重点证伪）**：本地未取整分与"官方先各自取整到两位再加权"这两种
算法在五包上给出同一个两位小数，但**原理上会在 `.005` 边界附近差 0.01**——
若某包真值落在四舍五入边界 ~0.005 内，两种口径可能不同。当前无法区分，因为五包的
真值离最近的边界都有 0.0010 以上（最近的是 `cand_rounded` 的 90.5940 与
`cand_covprobe25` 的 90.4040，各差 0.0010）。
