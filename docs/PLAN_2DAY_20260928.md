## 1. 数值目标：93 分必须来自材料项（本条改变了主攻方向）

从审查 §2 与本轮独立复算（`S = 6.4e6/K + 40·D/M + 20·H/9999`，`D = 506,157,994`）：

```
基线（plan_merge2，sha 7976c97c…）  K=184494  M=535,792,670  H=9998  → S=92.47508
1 把刀      = +0.000188 分
100 万 kg   = +0.070658 分   ⇒ 100 万 kg ≡ 376 把刀 ⇒ 1 把刀 ≈ 2,660 kg
```

**硬上界**：即使刀数打到数据下界 `K=182340`、覆盖满分、**材料效率保持不动**，
`S(182340, M0, 9999) = 92.88687`。**⇒ 刀数线本身到不了 93，甚至到不了 92.89。**

**⇒ 93 分的差距只能由材料项填。** 两条等价的目标柱：

| 目标柱 | 刀数 | 成材率 | 约需减少账单 |
|---|---|---|---|
| 只动材料 | 184494（不变） | 94.469% → **95.781%** | **−7.35 百万 kg** |
| 刀材同时动 | 184494 → **183500**（−994） | 94.469% → **95.32%** | −4.79 百万 kg |

**这条把"窗口招式迭代"降级了**：它是刀材互换招式，§2 测出的全部已兑现增益
（+0.006562）折合 **≈9.3 万 kg**，是 7.35 百万 kg 需求的 **1.3%**。差的不是 0.003 分，
是**两个数量级的材料**。所以窗口线**不是通 93 的路**，它是一条尾部线。

（`93.0` 是研究情景线，`93.2` 是内部缓冲目标，**都不是排名保证**——审查 §2 已声明。）

## 2. 已兑现账的更正：把一阶求和换成精确一次评价

审查 §8.3 明确：**"即使批次互不冲突，各批相对同一基线计算的 delta_score 也不能直接当精确总增分：
先累加真实 delta_K、delta_M、delta_H，再评价一次完整计划。"** 我原来的一阶求和（+0.0069）违反这条，已改。

因为 `K` 与 `M` 都是**按批可加**的（各批互不相交，补丁只重写自己那一批），并集计划的精确值是闭式的：

```
窗口=2（15 批） ΣΔK=+4   ΣΔM=−52,063 kg      → K=184498  M=535,740,607
窗口=3（18 批） ΣΔK=+16  ΣΔM=−110,916 kg
并集（29 批，重叠 4 个批取两尺度较优者，其中仅 1058 需换）:
               ΔK=+17   ΔM=−138,331 kg      → K=184511  M=535,654,339
```

| 量 | v1 的一阶估计 | **v2 的精确值** |
|---|---:|---:|
| 并集增益 | +0.006937 | **+0.006562** |
| 本地分 | 92.482013 | **92.481638** |
| 官方 round(.,2) | 92.48 | **92.48** |
| 距 92.485 | −0.003 | **−0.0034** |

**闭式被我拿实测校验过**：同一个闭式对窗口=2 的 15 批算得 **92.478004**，
而 `window_ils` 第 1 轮实测 **92.477996**（差 1e-5）——所以"累加 ΔK/ΔM 再评价一次"这个方法是可信的。

**注意一件具体的事**：并集为了省材料**净加了 17 把刀**，被刀数项吃回 **0.0032 分**，
占材料收益的 **1/3**。审查 §8.3 说的"新增刀数会抵消收益"在本轮数据上是可量化的。

> 仍有不确定性：并集是**手选每批一条**拼出来的，不是 `window_ils` 迭代到不动点的结果。
> 迭代会给出**联合真值**（可能更好：凸性正反馈；也可能更差：手选在并集汇率下不再最优）。

## 3. 门禁实验**已执行**：反驳撤回，审查 §3 成立

v2 曾据本轮普查反驳审查 §3（"两轮探针已被 kicks 复现或超过"）。**v3 用审查 §8.2 自己给的判据实测后撤回。**

**标定**（同一台机器、同一入口计划 `plan_merge2`）：

| 侧 | 命令 | 成本 |
|---|---|---|
| 窗口算子 | `blank_step.py probe --window 2 --batches <15>` | **12 s / 15 批**（完整枚举 90 窗口，零截断） |
| 生产移动集 | `requant_batches.py patch --iters 0 --seeds 0 --kicks N` | 约 **0.15–0.24 s / kick / 批** |

**实测结果**：

| 批 | 窗口算子的招式 | 生产 kicks 能否找到 | 成本对比 |
|---|---|---|---|
| **591** | `dK=+1, dM=−8,134` | **能**（`kicks=100`，账单 284,707 → 276,573 kg、刀 142→143，与窗口算子**逐位相同**） | kicks ≈24 s vs 窗口 ≈0.8 s ⇒ **窗口便宜 ~30×** |
| **2255** | `dK=−1, dM=0`（我原称"单轮做不到的联合重拆分"） | **不能**：`kicks=150`（23 s）、`kicks=600`（91 s）均未找到 | **窗口 0.8 s 找到** |
| **1764** | `dK=+1, dM=−6,162` | **不能**：`kicks=150`（17 s）未找到 | 同上 |
| 其余 12 条 | — | **未测** | — |

**⇒ 结论（v3 更正）**：

1. **审查对**：这批招式**是生产移动集能表达的动作**，至少 591 已被 kicks 原样复现。
   我原来的"邻域不完备"（"根本没被枚举到"）**过强**——正确的说法是**成本差**，不是**可达性差**。
2. 但 **2255 在 600 次重启（≈100× 等 CPU 预算）内仍未找到**，而窗口算子 0.8 s 就找到。
   所以"**窗口算子是这些招式的廉价 oracle**"成立，"**能带来生产搜索拿不到的新收益**"不成立。
3. **纪律**：`kicks=600` 没找到 ≠ 不可达。这是**预算内未定**，按 §6 口径不得当负结果用；
   但**更不得**反向当成"窗口线有独占价值"的证据。

**动作**：窗口 2/3 线**保存收益、停止作为突破主线扩量**——
① 已兑现的部分按 §2 精确结算并走"实际合并 → 查同批冲突 → 完整校验 → 评分"；
② 不再为它扩预算，**也不再把窗口从 3 扩到 4 当作新的突破路线**（审查二轮反馈原话）。
在跑的窗口=2 ILS **不打断**（已投入，产出可能把本地分推过 92.485 这个显示分界），
但它**不再是主命题**。

## 4. 三条路线（**v3 排序：B 优先，A 只作诊断，C 暂缓**）

### 路线 A（**降级：只作小幅诊断**）：完整批次的联合配料——量"固定结构是否已经很紧"

按审查 §4.1，第一版**只固定现有订单支持集**（不改批次成员、不跨批重建，接缝结构与覆盖率集合不变），
对**五种坯型**各求一次，内部联合决定 `c_r`（并排根数）、`k_ir`（订单 i 在第 r 轮片段数）、
`n_r`（申报坯数）：

```
L_r = Σ_i s_i k_ir ∈ [48,148]        (L_r+2)·c_r·ell <= 60000
c_r <= floor(2000/diameter)          (L_r+2)·c_r·ell <= n_r·w
Σ_r k_ir·c_r >= P_i                  k_ir>=1 仅原正支持集
K_batch = Σ_ir k_ir + R              M_batch = w·Σ_r n_r
```

**这不是从零起一个新框架**——`blank_step.solve_window` 已经是它的一个窗口级特例
（联合 count+片段、DP 保投递与 48 t 下限）。A 的增量是三条：**五种坯型一起比**、
**count 域放到完整而不是 `c±spread`**、**求 `K≤κ` 下的材料前沿而不只是单点 dS**。

- 求解环境：审查 §4.2 指出仓库规则**商业求解器仅限 COPT**，不引入未经确认的商业依赖。
  所以优先**完整有限 count 域的整数模型 + 短名单 beam 兜底**；**若只保留 count 短名单或设 beam，
  必须改称启发式，不得声称域内最优**（审查 §4.2 的硬要求）。
- 必须产出**非支配前沿**（审查 §4.3）：对若干刀预算 `κ` 分别最小化材料，保留不被支配的 `(K,M,H)`；
  旧轮型上排名第三的坯型可能在新配置下胜出。
- **A 的判断价值**（审查 §4.4）：① 能构造明显更好的合法配置 → 说明现有数值搜索漏了组合；
  ② 得到接近当前解的有效最优性界 → 固定支持内重启价值小，**转 B**；
  ③ 超时且上下界很宽 → 只能说这个方法暂时不合算。
- **v3 的预算上限**：A **不是主线**，只做→ **2–3 个代表性批**的小样，
  用途仅限回答一个是非题：**固定结构是不是已经很紧？** 答案不是"找到更好解"就扩量，
  而是把它当作 B 的**启动信号**（"固定形状很紧" ⇒ 必须换形状 ⇒ B）。
  审查 §9 给 A 的阶段门原话：原型最多半天，诊断总计**不超过一天**。

### 路线 B（**v3 主线**）：合法订单链重排 + 轮边界重建

**这一节是 v3 的主命题。** 已有基础设施不用重写：`tools/analysis/chain_layout.py` 已经解决
"把订单展平成链、每个边界最多一个订单跨接"的**零错误布局**（3,207 schemes / 0 errors / 9,999 订单全落），
而它的订单序列**由 `sorted(totals, key=-totals[o])` 写死**——**序列本身就是 B 要扰动的那个变量**。

审查 §5.1 的判断：现有接缝**大量是单订单交班**，规则限制了"一个接缝同时跨几个订单"，
但**没有规定必须由这个订单交班、也没规定别的订单排列不变**。B 放开：订单排列、每轮包含的订单、
跨轮订单身份、分轮位置、轮数、每轮 count（**第一阶段仍固定批次成员**）。

- 合法表示（审查 §5.2）：订单排成序列，每个订单的交付是**连续块**，序列切成**至多六轮**，
  轮边界最多切开一个订单；同一订单连跨多轮时，**中间轮只能承载该订单**。
  这是**充分构造**，不声称覆盖平台全部合法形状；**轮内键序由构造生成，不能事后任意排序**。
- 状态 = "完成前缀 + 当前订单未交付件数 + 已用轮数" + 是否已获共享覆盖；保留 `(K,M,H)` 非支配标签，
  **不能只留最低材料路径**；五种坯型各跑一遍，**同一方案内不得给不同轮选不同坯型**（审查 §5.2）。
- 第一版**只做三种序列变化**（审查 §5.3）：相邻交换 / 短块插入 / 三订单重排。
  **关键是"交换后从合法表示重新求轮"，不是把旧轮的订单挪过去并容忍接续违规；只调 JSON 键序不算。**
- 首个交付物（审查 §5.5）**不是全卷预测分表**，而是**可核对的前后对照**：
  旧/新订单链、旧/新每轮 count、旧/新整数坯数、旧/新 K/M/H、严格校验、精确全局 ΔS、
  **等预算生产精修的最好结果**、种子与候选版本。

**v3 把它收成一个可判定的验收样例**（审查二轮反馈原话："下一项最有价值的交付应当很具体"）：

> **在同一批订单上，找到一个改变了订单链或接缝身份、合法、且优于等预算生产精修的真实样例。**
> **找不到就限时停止；找到了，再研究同类机会有多少。**

实验设计（**控制变量是"链"，不是预算**，这样才排除"多花时间就赢"的解释）：

| 臂 | 起点 | 预算 |
|---|---|---|
| **对照** | 该批在 `plan_merge2` 里的现有链 | 生产精修（`polish` / `iterated_polish`）**等 CPU** |
| **处理** | 同批订单，**链被扰动后重新布局**（相邻交换 / 短块插入 / 三订单重排，各跑一遍） | **同一份**生产精修，**同一 CPU** |

判定：`val(处理) < val(对照)` **且**整卷 `platform_check` 通过 **且** 订单支持集/轮边界确实变了。
**只改了数值没改订单支持或轮边界 ⇒ 归入 A，不冒充结构突破**（审查 §5.5）。
**限时**：先只做**一个批**；这条样例找不到，就按审查 §9 的 B 阶段门**关闭 B**并把结论写进 CURRENT。
- **升级门槛**：若所有改善都能被生产版 kicks 在更低成本下复现，B **不升主线**；
  若 B 只改了数值没改订单支持或轮边界，**归入 A，不冒充结构突破**（审查 §5.5）。

### 路线 C（**v3 明确暂缓**）：完整合法方案池的组合选择

**启动条件（审查 §6）**：B 已能稳定生成不同合法形状，且已有少量同组批次成员变化的合法候选。
否则不开发主问题。列生成：每列是一个完整合法方案，`Σ_{p: i∈O_p} x_p = 1` 保证订单恰好归属一列，
**禁止跨方案拆单**，原方案全留在池里 ⇒ 组合问题**恒有原计划可回退**。
**池内最优 ≠ 全局最优**（审查 §6 明确）。

重启预算按"近期单位时间实际增益"分配，成熟精修保留 **20%**，连续两档追加无收益的批**暂停**。
