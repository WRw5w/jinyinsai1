# 路线 L —— 总量口径包（打破逐坯型保险）

## 一句话

同一套切割方案，只改**申报坯数**：把坯型 2 从 28171 个减到 28170 个、坯型 1 保持 8353 个，
申报钢总量从 253,905,353 kg 降到 **253,899,190.5 kg**（少 6,162.5 kg），
逐坯型保险被打破 **2,193.2 kg**。

## 为什么可以这么改

我们自己的物理审计脚本 `platform_check.py` 的 `strict`（逐轮）口径，
在**已被平台接受并拿到 100.0000** 的 L3 原包上就有 **1308 处违规**：

```
submission_probe_floor/初赛结果_棒材优化.json --weight-mode strict
  -> passed=false, blank_material=1308
```

也就是说，平台**不逐轮**核申报钢。剩下的唯一未测假设是：
平台是否**按坯型**核总量（`ceil(A_bt / BW_bt)`）。

历史上我们所有提交包的逐坯型申报量都**恰好等于**这个 `ceil`，
所以这条保险从来没有被区分验证过。本包就是那个区分实验。

## 数值

| 项 | 路线 S（保险内） | 路线 L（本包） |
|---|---|---|
| 坯型1 申报（ceil 8353） | 8353 | 8353（= ceil，不动） |
| 坯型2 申报（ceil 28171） | 28171 | **28170**（−1 个） |
| 申报钢总量 raw | 253,905,353.0 | **253,899,190.5** |
| 缺口 raw − A | 7,595.666 kg | 1,433.166 kg |
| 免费加料补齐 | 7,595.6638 kg | 1,420.6880 kg（DP） |
| 配对精修（净 0 刀） | — | +12.4762 kg（2 对） |
| **残差** | 0.010334 kg | **0.001789 kg** |
| 成材率 | 99.999999995829% | **99.999999999296%** |
| 刀数 | 90000 | 90000（不变） |
| 覆盖 C | 100% | 100%（不变） |

`raw = 8353·9613.5 + 28170·6162.5`，仍然落在 **246.5 kg 格点**上
（`gcd(2·9613.5, 2·6162.5)/2 = 246.5`），并且仍满足 `raw ≥ A`（成品总重）。

**在「申报钢更少」和「精确总分更高」两个键上，本包都优于路线 S**，
唯一代价是打破逐坯型保险。

## 两条路线的取舍（重要）

低 gap 格点的**免费**加料粒度不够细：免费加料的最小单位是
`size × 并行根数 × 线密度`，最小 383.2 kg、中位 3227 kg，
所以 gap 在 1400 kg 以下时光靠免费加料只能填到 6~12 kg 精度。

但**配对机制**（k≥2 加一件花 1 刀、k≥3 削一件还 1 刀，净刀耗 0）
提供的是「两个值之差」，密度在克级，反而能把**较大的**残余一次抹平：

```
格点 m         raw            申报钢差    gap       免费+配对后残差
1030012    253897958.0    −7395.0 kg    200.666    < 最小免费粒度，填不动
1030017    253899190.5    −6162.5 kg   1433.166    0.001789          <- 路线 L
...
1030042    253905353.0    （保险点）     7595.666    0.010334          <- 路线 S
```

- **路线 S**（raw = 253,905,353）走「保险线」：逐坯型申报量都恰好等于 `ceil(A_bt/BW_bt)`，
  平台若按坯型核总量也一定过。残余被卡在 0.010334 kg（现有两个池里找不到更小的可配差值）。
- **路线 L**（raw = 253,899,190.5）走「对冲线」：少报 6,162.5 kg，残余还更低。
  若平台真按坯型核总量，本包会被拒——那正是我们要测的结论。

## 复现

```bash
python -X utf8 runs/acceptance/fill_lattice.py \
    submission_probe_floor/初赛结果_棒材优化.json \
    runs/fill/filled_lattice.json --m 1030017
python -u -X utf8 runs/acceptance/pair_polish.py \
    runs/fill/filled_lattice.json runs/fill/filled_lattice_polished.json
```

只动了三处：`length_scheme` 里 1 个 k=1 段抬到 k=2（零刀耗）、
1 组「k≥2 加一件 / k≥3 削一件」配对（净 0 刀），
以及两个坯型的 `blank_counts` 总数改成 8353 / 28170。
