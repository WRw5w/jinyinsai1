# 复赛交付：代码 / 模型 / 环境说明

**队名**：棒材优化　**轮次**：复赛　**对应结果**：`复赛结果_棒材优化.zip`

---

## 1. 运行环境

| 项 | 值 |
|---|---|
| 语言 | Python **3.13.12** |
| 操作系统 | Windows 11（代码不依赖平台，Linux/macOS 同样可运行） |
| 第三方依赖 | **无**。仅用标准库：`math` `json` `csv` `zipfile` `decimal` `itertools` `collections` `pathlib` `tempfile` `hashlib` `argparse` `math.ceil/floor` |
| 硬件 | 任意；可**按键多进程**加速（`--jobs N`，`N=0` 取 CPU 核数），单进程也正确。整卷构建见 §5 |
| 编码 | 源码 UTF-8；复赛原始数据为 **GBK**，由 `prepare_semi.py` 显式按 GBK 读取 |

> 没有 `requirements.txt` 是刻意的：全链路零第三方依赖，评审机器上无需安装任何包。

## 3. 复现步骤

在包根目录（含 `code/` 与 `data/`）执行：

```bash
# 0) 让 code/ 里的模块可被导入（Windows 用 set PYTHONPATH=code）
export PYTHONPATH=code

# 1) 复赛数据归一化 + 异常订单审计（重跑会重新生成 data/semi/*.normalized.csv）
python -X utf8 code/prepare_semi.py

# 2) 全卷构建：分组 → 连续性定形 → 容量/净长感知装桶 → 12 点 λ 扫描 → 三层校验
#    产出 runs/cont_deliver25/result.json + summary.json（交付方案即此文件，λ=4800）
#    --jobs 0 取 CPU 核数按键并行（16 核实测 431 秒；--jobs 1 为单进程，结果逐字节相同）
python -X utf8 code/build_semi_plan2.py --out runs/cont_deliver25 --sweep --cap-ratio 0.25 --jobs 0

# 3) 打包为单 JSON 的 ZIP，并重开 ZIP 字节做三层复验
#    --no-merge：源方案已按 clause 6 定形，逐字节原样写入，不做任何轮次合并
python -X utf8 code/build_submission.py \
    --input runs/cont_deliver25/result.json --round semi --data data/semi \
    --orders data/semi/orders.normalized.csv \
    --blanks data/semi/blanks.normalized.csv \
    --config data/semi/cap025.config.json \
    --audit data/semi/data_audit.json \
    --output-dir out --no-merge

# 4) 未决口径敏感度复算（重算报告 §6.2 / §6.3 的每一个格子）
python -X utf8 diagnostics/semi_hypothesis_table.py

# 5) 单元与对拍测试（discover 会把 code/ 加入 sys.path）
python -X utf8 -m unittest discover -s code -p "test_*.py"

# 6) λ 选点对基准刀数的敏感性（报告 §6.7）
#    6a) 旧定形族（round_shaper + build_semi_plan.pair_group），11 点 λ × 2 刀口径 × 3 基准，
#        约 70 s 配对 + 11 次评分；§6.7.2 的历史对照，用来演示「λ 最优随 B 移动」这一机制
python -X utf8 diagnostics/semi_lam_baseline_sensitivity.py
#    6b) **交付定形族**（continuity_shaper + r=0.25），12 点 λ × 2 刀口径 × 3 基准，§6.7.1。
#        需要先落盘候选表（一次性，约 7 分钟；随后 λ 网格秒级重跑）：
python -X utf8 code/build_semi_plan2.py --out runs/cont_dump25 --sweep --cap-ratio 0.25 \
    --jobs 0 --dump-candidates runs/cand25.json
python -X utf8 diagnostics/semi_lam_delivery_family.py
```

> 第 2 步是**确定性**的：`build_semi_plan2.py` 不含随机数，同一输入必得同一输出，
> 所以 `result/复赛结果_棒材优化.json` 可被逐字节复核。本轮把这条断言从"单键回归"
> 升到**全卷**：两次完全独立的 16 进程全卷构建（`runs/cont_deliver25` 与
> `runs/cont_dump25`，各自跑完 12 点 λ 扫描与四道闸门）产出 892,512 B、SHA-256 同为
> `d19360c548c3b01b4cd8d5a5ce7ee8051d7f2053c93d8a6236768838b85f73b6` 的 `result.json`，
> 且两次都选中 λ = 4800 / 176,563 刀 / 93.187 分。`--jobs` 只改变**执行方式**
> （按键独立并行），汇总时按原始键顺序重排，`--jobs 1` 与 `--jobs 4` 产出的
> `result.json` SHA-256 完全相同（已实测）。
> ⚠️ 第 3 步必须显式传 `--data data/semi`：`--round semi` 已按复赛规则校验，
> 但若漏传 `--data`，独立校验器会去读初赛目录，属于静默用错数据。
> ⚠️ 第 3 步必须带 `--no-merge`：默认的 `merge_compatible` 会把整方案装箱重排，
> 那是给旧 `round_shaper` 方案用的；对已定形的连续性方案做拼接会重新引入
> clause 6 违规（平台第一次提交的 7,559 条违规即由此产生）。

## 4. 测试与三层验证

| 层 | 是什么 | 本次结果 |
|---|---|---|
| `platform_check.check` | 独立校验器：直接读**原始 GBK CSV** 与提交 JSON，重算整数倍长度、含余量的床长/承重、床宽、交付数量、钢坯物料、条款 7/8 下界、相邻轮连续性、同轮覆盖率 | **`passed = True`**，19 类 error kind 全为 0 |
| `solver.validate_plan` | 求解器自带校验，与 `make_round` **不同实现**（`blank_rule='per_round'`），并检查 `pieces ≤ produced ≤ caps`、每单质量下界、跨方案唯一性、连续性 | **通过**，`rounds = 9,914`，`coverage = 1.0` |
| `platform_score.evaluate` | 评分模型，复赛 `Rules.semi()`：`knife_add_per='round'`、`coverage_shared=True`、`max_rounds=6`、`numerator_capped_by_demand=True` | **`violation_count = 0`**，本地总分 93.187（B=160,000）/ 77.329（B=90,000） |
| `diagnostics/semi_continuity_audit.py` | clause 6 官方判据反推与审计（相邻两轮集合不得完全相同 + 订单轮次不得跳轮） | **PASS**：C = 0 条、跳轮 = 0 条（旧包上可复现官方的 7,559 条） |

`build_submission.py` 在打包后**重新打开 ZIP 内的实际字节**再跑一遍第 1、2 层，
并比对 SHA-256，确保「被校验的对象」就是「被提交的对象」。

## 6. 需要声明的口径

1. **超产上限是求解设置**，不是官方规则。题目 12 条约束中没有超产上限，第 7、8 条
   均为单边下界（「不低于」）；`RULES.md` 载明复赛「超产不扣分，但超产部分不计入
   成材率」。交付方案取每单超产允量 **25%**，**实际超产量 2.87%**（按重量）。因为
   `r` 是求解设置而非规则，本包同时提供四档配置
   （`data/semi/{cap002,cap005,cap010,cap025}.config.json`），改 `--cap-ratio`
   与 `--config` 重跑第 2、3 步即可得到备选包；各档的刀数、成材率与四种口径下的
   分数见报告 §6.2 / §6.3。
2. **基准刀数与时间子分口径未获官方确认**。本包全部总分为本地模型结果，
   不代表已取得官方评分器源码。四种读法下的分数见报告 §6.3。
   ⚠️ **基准刀数 B 不只决定绝对分数，还决定 λ 的选点**：本版在 B = 160,000 下由
   12 点扫描选出 **λ = 4800**，且是**内部**最优（相邻点 93.183 / 93.176 / 93.167），
   不是网格边缘。`r = 0.25` 在四种读法下距行内最优 ≤ 0.25 分，该稳健性结论不受
   未决口径影响。报告 §6.7 给出两张「族内最优 λ 随 B 移动」的表：第 1 张是**旧定形族**
   （`round_shaper`，交付点 λ=2400），第 2 张是**交付定形族**
   （`continuity_shaper` + `r = 0.25`，交付点 λ=4800）——**交付以第 2 张为准**。
3. **`length_scheme` 只写净定尺整数倍**，不含切损；整轮统一加 2 m 余量计算长度与
   承重（`length_mode = net_shared_trim`），与复赛口径一致。
4. **异常订单**按题面允许的过滤流程隔离，原始文件未改动，未虚构订单或补值。
