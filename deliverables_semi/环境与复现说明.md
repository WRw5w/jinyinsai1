# 复赛交付：代码 / 模型 / 环境说明

**队名**：棒材优化　**轮次**：复赛　**对应结果**：`复赛结果_棒材优化.zip`

## 1. 运行环境

| 项 | 值 |
|---|---|
| 语言 | Python **3.13.12** |
| 操作系统 | Windows 11（代码不依赖平台，Linux/macOS 同样可运行） |
| 第三方依赖 | **无**。仅用标准库：`math` `json` `csv` `zipfile` `decimal` `itertools` `collections` `pathlib` `tempfile` `hashlib` `argparse` `math.ceil/floor` |
| 硬件 | 任意；整卷构建为**单进程单核约 1 分钟**，内存峰值 < 1 GB |
| 编码 | 源码 UTF-8；复赛原始数据为 **GBK**，由 `prepare_semi.py` 显式按 GBK 读取 |

> 没有 `requirements.txt` 是刻意的：全链路零第三方依赖，评审机器上无需安装任何包。

## 3. 复现步骤

在包根目录（含 `code/` 与 `data/`）执行：

```bash
# 0) 让 code/ 里的模块可被导入（Windows 用 set PYTHONPATH=code）
export PYTHONPATH=code

# 1) 复赛数据归一化 + 异常订单审计（重跑会重新生成 data/semi/*.normalized.csv）
python -X utf8 code/prepare_semi.py

# 2) 全卷构建：分组 → 邻接配对 → 逐方案重定形 → 9 点 λ 扫描 → 三层校验
#    约 1 分钟；产出 runs/capx_0.10/result.json + summary.json
python -X utf8 code/build_semi_plan.py --out runs/capx_0.10 --sweep --cap-ratio 0.10

# 3) 打包为单 JSON 的 ZIP，并重开 ZIP 字节做三层复验
python -X utf8 code/build_submission.py \
    --input runs/capx_0.10/result.json --round semi --data data/semi \
    --orders data/semi/orders.normalized.csv \
    --blanks data/semi/blanks.normalized.csv \
    --config data/semi/cap010.config.json \
    --audit data/semi/data_audit.json \
    --output-dir out

# 4) 未决口径敏感度复算（重算报告 §6.2 / §6.3 的每一个格子）
python -X utf8 code/../diagnostics/semi_hypothesis_table.py

# 5) 单元与对拍测试（discover 会把 code/ 加入 sys.path）
python -X utf8 -m unittest discover -s code -p "test_*.py"

# 6) λ 选点对基准刀数的敏感性（§6.7；11 点 λ × 2 刀口径 × 3 基准，约 70 s + 11 次评分）
python -X utf8 code/../diagnostics/semi_lam_baseline_sensitivity.py
```

> 第 2 步是**确定性**的：`build_semi_plan.py` 不含随机数，同一输入必得同一输出，
> 所以 `result/复赛结果_棒材优化.json` 可被逐字节复核。
> ⚠️ 第 3 步必须显式传 `--data data/semi`：`--round semi` 已按复赛规则校验，
> 但若漏传 `--data`，独立校验器会去读初赛目录，属于静默用错数据。

## 4. 测试与三层验证

| 层 | 是什么 | 本次结果 |
|---|---|---|
| `platform_check.check` | 独立校验器：直接读**原始 GBK CSV** 与提交 JSON，重算整数倍长度、含余量的床长/承重、床宽、交付数量、钢坯物料、条款 7/8 下界、相邻轮连续性、同轮覆盖率 | **`passed = True`**，19 类 error kind 全为 0 |
| `solver.validate_plan` | 求解器自带校验，与 `make_round` **不同实现**（`blank_rule='per_round'`），并检查 `pieces ≤ produced ≤ caps`、每单质量下界、跨方案唯一性、连续性 | **通过**，`rounds = 12,559`，`coverage = 0.9999` |
| `platform_score.evaluate` | 评分模型，复赛 `Rules.semi()`：`knife_add_per='round'`、`coverage_shared=True`、`max_rounds=6`、`numerator_capped_by_demand=True` | **`violation_count = 0`**，本地总分 78.001（B=90,000） |

`build_submission.py` 在打包后**重新打开 ZIP 内的实际字节**再跑一遍第 1、2 层，
并比对 SHA-256，确保「被校验的对象」就是「被提交的对象」。

## 6. 需要声明的口径

1. **超产上限是求解设置**，不是官方规则。题目 12 条约束中没有超产上限，第 7、8 条
   均为单边下界（「不低于」）；`RULES.md` 载明复赛「超产不扣分，但超产部分不计入
   成材率」。交付方案取每单超产允量 10%，**实际超产量 1.67%**（按重量）。若官方
   另有隐性上限，改用 `data/semi/competition.config.json`（r=0.02）重跑第 2、3 步
   即可得到备选包。
2. **基准刀数与时间子分口径未获官方确认**。本包全部总分为本地模型结果，
   不代表已取得官方评分器源码。四种读法下的分数见报告 §6.3。
   ⚠️ **基准刀数 B 不只决定绝对分数，还决定 λ 的选点**：交付选点 λ = 2400 只在
   (floor, B=90k) 与 (nearest, B=160k/180k) 上是最优，在 (floor, B=160k/180k) 与
   (nearest, B=90k) 上族内最优点分别是 λ = 4800 / 1200 / 1600，差距 0.0552 / 0.2134 /
   0.0417 分（报告 §6.7，脚本 `diagnostics/semi_lam_baseline_sensitivity.py`）。
   `r = 0.10` 在四种读法下都距行内最优 ≤ 0.25 分，该稳健性结论不受影响。
3. **`length_scheme` 只写净定尺整数倍**，不含切损；整轮统一加 2 m 余量计算长度与
   承重（`length_mode = net_shared_trim`），与复赛口径一致。
4. **异常订单**按题面允许的过滤流程隔离，原始文件未改动，未虚构订单或补值。
