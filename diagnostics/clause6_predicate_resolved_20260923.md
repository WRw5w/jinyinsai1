# Clause 6「跨轮接续不连续」判据辨析（2026-09-23 定案）

> 结论先说：官方判据是 **B**，不是包内另一条交付线在 `platform_score.py` 里
> 校准成的 **C**。两者在事故包上差 187 条，在**对方的重交版**上差 6230 条。
> 若对方按现包提交，大概率再吃一次 0 分。

## 1. 三个候选读法

对每个方案，遍历相邻两轮 `(左, 右)`：

| 代号 | 判据 | 依据 |
|---|---|---|
| **B** | 左∩右 ≠ ∅ **且** `last(左) != first(右)` | 官方 7030 反馈 |
| **C** | `set(左) == set(右)` | 对方 `platform_score.py:297` 的"校准" |
| **G** | 某订单的轮次编号不连续（per-order gap） | 对方已排除（量级差 10×） |

`last(左)` / `first(右)` 指轮次字典的**键顺序**首尾，不是集合首尾。

## 3. 违规实例（对方包，方案 0）

```
轮1: B20273518→29.4  B20271397→22.1                    末尾 = 397
轮2: B20273518→34.3  B20271397→11.05  B20271731→4.9    开头 = 518
```

订单 `518` 在轮1 切了 29.4、轮2 又切 34.3，**两段之间插进了订单 397**。
集合不同（`{518,397}` vs `{518,397,731}`），故 C 看不见；键顺序首尾不符，故 B 命中。

我方方案 0（已修）：

```
轮0: 28→49.0  27→31.8     末尾 27
轮1: 27→26.5  28→49.0     开头 27     ✅ 首尾相接
```

集合相同、首尾相接 —— 同一批订单换序再切，合法。**B 静默，C 也会静默**，
但 C 在别处会误伤（见第 4 节）。

## 4. C 是"过宽"还是"过严"？

**两者都是，方向取决于结构**：

- 对 `FIXED` 包，C 报 6532 条，而 B 报 0 —— C **过严**（把合法的换序轮对
  当成违规）。我方若听信 C，会去"修"一个根本不需要修的包，白丢分数。
- 对对方包，C 报 0，B 报 6230 —— C **过宽**（漏掉全部真违规）。

所以 C 不是 B 的近似，两者**互不包含**。这正是必须钉死判据的原因。

## 5. 代码现状

- `platform_check.py` 同时实现两条子规则，均在 `spec['continuity']` 下：
  - `continuity` = 判据 G（订单轮次不连续）
  - `continuity_seam` = 判据 B（跨轮交界首尾不符）
  - 文件内注释已写明为何**故意不实现 C**。
- `build_submission.py:rotate_scheme_rounds` 在复赛打包时旋转每轮键顺序，
  使每条 seam 闭合；**只动顺序、不动 `(订单→长度)` 多重集**，故分数逐位不变。
- `test_semi_check.py` 新增 `test_seam_predicate_is_not_the_weaker_set_equality_rule`，
  构造"集合不同但首尾相接"（B 静默）与"集合相同但首尾不符"（B 命中）两个
  正反例。若有人把判据简化成 C，此测试立即失败。

## 6. 遗留不确定性（必须诚实标注）

1. **官方源码未公开**，B 是从**一次** 7030 反馈反推的。上面用 C 在 7030 上
   差 187 把它排除，但反推法无法排除"B 与真规则在未见样本上分歧"。
2. 官方给的定位串是 `方案a批j` 粒度，与 B 的"每 seam 计一条"一致；
   G 是 per-order 粒度、量级不符，已被排除。
3. **可查证的边界**（官方反馈未覆盖，建议后续用便宜包试探）：
   - 两轮交集**多于一个**订单（我方 `merged_v2` 有 7034 处交集、7030 处违规，
     恰好 4 处因 `last == first` 豁免 ⇒ 多交点不额外计费，支持 B）；
   - 两轮**无**交集（B 静默，官方未给反例）；
   - 同一订单**跳轮**（由 `continuity` 单独计，与 seam 不重叠）。
4. **对对方的建议**：把校验器从 C 换成 B 再自检；按 B，其现包 6230 条违规，
   总分应为 0 而非 93.187。这是需要他们自己决定的事，我方不代为改包。
